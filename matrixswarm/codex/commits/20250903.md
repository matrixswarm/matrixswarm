Commit: Security + Spawn Control Hardening

### Highlights
## Note: all cert and signing keys are generated and stored in the vault, stored as a deployment in the Phoenix Cockpit GUI
- **Unified HTTPS + WSS Security**
  - Both transports now enforce the same trust chain: TLS + SPKI pinning + signed hello + signed payloads.
  - HTTPS: connect timeout, SPKI pin verification, disabled CA validation when pinned.
  - WSS: removed manual upgrade, fixed self-signed cert blocking, disabled idle recv timeout (server pings keep alive).
  - All messages use `{ "sig": "...", "content": {...} }` format; tampered payloads rejected with `[SIG DENY]`.

- **Signed Hello Handshake**
  - Hello packet from clients now signed with agent private key.
  - Server verifies using peer public key; binds session only on success.
  - Logs `[WS][HELLO] signature accepted` before session is marked active.

- **Spawn Lifecycle Hardening (clear_to_spawn + punji)**
  - New `clear_to_spawn()` ensures agents only respawn if heartbeat files are stale or missing.
  - Punji lifecycle:
    - Spawner drops punji if a matching process exists.
    - Agent detects punji in `enforce_singleton`, exits gracefully, and deletes punji file.
    - If agent ignores, spawner escalates with SIGTERM → SIGKILL (`reeeeeeebaaaangaaaaa()`).
  - Prevents “flip-tripping” where stale punji files killed fresh spawns.

- **File Hygiene & Resilience**
  - `check_heartbeats` now returns `None` if no poke files exist (clearer semantics).
  - Stray `poke.*` files are auto-cleaned during spawn checks to prevent phantom restarts.
  - `process_utils.find_jobs_by_prefix` hardened against `None` cmdlines; supports exact/prefix matching.
  - Punji cleanup happens on both agent exit and spawner escalation → no stale traps left behind.

Summary
This operation unified transport security (HTTPS + WebSocket) with spawn lifecycle hardening (punji enforcement, singleton cleanup).
Result:

Cryptographically identical HTTPS + WSS — TLS + SPKI + signed hello + signed payloads.

Reliable spawn control — punji files now act as traps but are always cleaned up (agent or spawner side).

No more flip-trips — stale punji or poke files cannot block fresh spawns.

Disabled CA verification (CERT_NONE) when SPKI pinning is enforced.

Spawn Lifecycle Hardening
process_utils.py

find_jobs_by_prefix:

Guards against None cmdlines from psutil.

Supports match_mode="exact" or "prefix".

reeeeeeebaaaangaaaaa():

Sends SIGTERM, waits, then SIGKILL survivors.

Returns log-friendly status string for BootAgent.

boot_agent.py

clear_to_spawn (new unified controller):

Run check_heartbeats:

If threads alive/sleeping → skip respawn.

Else → proceed to checks.

Clean stray poke.* files to avoid phantom stale triggers.

Look up processes via find_jobs_by_prefix.

No matches → clear_to_spawn = True; also delete stale punji.

Matches, no punji → drop punji file in incoming/.

Matches + punji still present → escalate with reeeeeeebaaaangaaaaa() (SIGTERM/SIGKILL).

enforce_singleton:

Detects punji file → logs [ENFORCE] hit punji — exiting....

Breaks loop and self-terminates.

Deletes punji file on exit to prevent “flip-tripping” new spawns.

spawn_manager:

Calls clear_to_spawn() before each spawn attempt.

Enforces cronjob rules (mission.complete + interval).

Guarantees punji lifecycle between spawner + agent.

Rationale

Before:

HTTPS signed, WSS unsigned.

Self-signed CA chains caused Python SSL failures.

Punji files could persist and kill new spawns.

Agents sometimes flip-tripped on old poke/punji files.

Now:

HTTPS + WSS enforce the same trust chain: TLS + SPKI + signed hello + signed payloads.

Punji lifecycle is two-sided:

Spawner: drops punji, escalates if agent ignores.

Agent: enforces punji in enforce_singleton, dies gracefully, cleans punji.

No stale files remain to trip new agents.

Verification

Transport:

HTTPS + WSS reject tampered packets with [SIG DENY].

Self-signed certs accepted with SPKI pin enforcement.

Idle WSS connections remain stable via server ping keepalive.

Spawn lifecycle:

Dropping punji → agent logs exit, cleans punji.

If agent ignores punji → spawner escalates with SIGTERM/SIGKILL, then cleans punji.

Cronjobs respect interval enforcement via mission.complete files.

No stale poke.* files cause phantom spawns.

🪖 Operational Notes

Punji = trap file. Dropped by spawner to trigger graceful self-termination.

Escalation = SIGTERM → SIGKILL if punji ignored.

Heartbeat check ensures only failed agents are respawned.

Unified signing reduces attack surface — all traffic looks the same (sig + content).

Logging unified:

[BOOT][PUNJI] for trap lifecycle.

[ENFORCE] for singleton exits.

[SIG DENY] for signature failures.
